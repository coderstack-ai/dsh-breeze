# README-AI — 给 agent 的运行时说明

> 这份文档是给**运行时 agent**看的，不是给人看的。人看 [README.md](README.md)。
> 目标：装完、配完、验证完，全部由你完成，人只负责听。

## 一、你的工具有什么

| 工具 | 什么时候用 |
| --- | --- |
| `breeze_status` | **任何 breeze 调用失败后的第一步**。区分「服务没起」和「音色 id 错了」 |
| `breeze_config` | 改地址、token、默认音色、默认指令、输出目录。改完立即生效，**不需要重启** |
| `breeze_voices` | 挑音色前先列一遍。返回里有 `refText` 和 `description` |
| `breeze_speak` | 真正的产出：文字 → 音频文件 |
| `breeze_voice_save` | 有一段参考音频、想反复用同一个声音时，存成 id |
| `breeze_voice_delete` | 从服务内存卸载音色（文件还在，重启会回来） |
| `breeze_convert` | 保表演换音色。experimental，慢，最好别当默认路径 |

## 二、第一次接一个服务，按这个顺序

1. `breeze_config({ action: "set", fields: { baseUrl: "<URL>" } })` —— 有反向代理鉴权就一起 `token`。
2. `breeze_status()` —— 看 `reachable`。
   - `false` 且 `note` 里有 `connection refused` ⇒ 服务没起。
   - `false` 且 `note` 里有 `401` ⇒ token 错了或没带。
   - `false` 且 `note` 里有 `host not found` ⇒ URL 拼错了。
3. `breeze_voices()` —— 拿到真实存在的音色 id。**不要猜 id**：服务端对未知 id 回 `404`，不会退化成默认声音。
4. `breeze_speak({ text: "测试", voice: "<上一步的 id>" })` —— 出文件即通。
5. 把文件路径交给 `present`，人会自己点开听。

## 三、参数怎么给

| 你想让它 | 给什么 |
| --- | --- |
| 用某个已存声音 | `voice: "<id>"` |
| 现场描述一个声音（没有现成音色） | 不给 `voice`，给 `instruction` |
| 模仿一段音频 | `refAudioPath` + **逐字准确的** `refText` |
| 让笑声/叹气真的出现 | `cfgScale: 2` ~ `3`，并把事件写进文本：`(sigh) ...` / `[叹气] ...` |
| 复现同一段音频 | 同 `text` + `voice` + `instruction` + `seed` |
| 短句快速出结果 | 默认就行 |
| 长文本narration | 默认分句（`splitChars` 不传）比 `splitChars: 0` 稳；一次性长文本模型会走神 |

`instruction` 的写法：**一句话说清五件事**（年龄 / 性别 / 音色 / 语速 / 情绪），并且**语言跟朗读文本一致**——中文文本配中文描述，英文配英文。这是官方要求，不是风格建议。

## 四、四个会静默出错的坑

1. **`instruction` vs `instructions`**：服务端两条路径字段名不同——表单用单数，OpenAI 风格 JSON 用复数。写错**不报错、照样回 200、指令被丢掉**。本插件的表单路径用单数、mp3 的 JSON 路径用复数，你别绕过工具手搓请求。
2. **WAV 头里的 `0xFFFFFFFF`**：服务端流式返回 wav 时长度未知，两个 size 字段都是最大值。本插件一律要原始 PCM 自己封 44 字节头；收到 wav 时会把两个 size 修好。**你自己 curl 出来的 wav 可能不被严格播放器接受**，别拿它当证据。
3. **`409 busy`**：不是错误，是「每个生成槽位都被占了」。插件内部会退避重试；如果最终还是失败，等几秒再来，别改配置。
4. **音色名不能有中文**：名字要变文件名，服务端会拒。用字母数字、`-`、`_`。

## 五、验证自己真的做对了

- **出文件 ≠ 成功出声**。检查 `breeze_speak` 返回的 `durationSec > 0.5` 且 `bytes > 20000`；只有几百字节通常是空音频。
- **指令真的生效了吗**：同一个 `text` + 同一个 `seed`，跑一次带 `instruction`、一次不带，比 `durationSec`。**时长几乎一样 ⇒ 指令被丢了**（多半是字段名走错路径）。这个判据能证伪，比「返回 200 就算成功」硬。
- **别拿旧文件当新证据**：`breeze_speak` 每次都生成新文件名（带时间戳 + 随机后缀），报给人之前确认路径就是本次返回的那个。

## 六、边界（别承诺做不到的）

- 不替你装服务端：几 GB 权重 + 显卡驱动，只能人来做。
- 不判断音色好不好听：只能证明文件合法。
- 服务端本身没有鉴权/限速：不要把它绑到公网，也不要因为插件能带 token 就以为服务安全了。
- 权重是非商业许可；克隆任何人的声音前先取得同意。
